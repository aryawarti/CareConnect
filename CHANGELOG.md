# Changelog

All notable changes to CareConnect. Format follows [Keep a Changelog](https://keepachangelog.com); the project is pre-1.0, so expect breaking changes between minor versions.

## [Unreleased]

### Added — deployment

- **The full architecture now deploys to a single VM** — not a reduced version of it. Eleven services, eight databases and Kafka, each in its own container, behind Caddy for TLS, on a single 8 GB VM (Oracle Cloud Always Free A1, Hetzner, or any equivalent — the runbook is not provider-specific). The alternative on the table was a free static host plus a container PaaS, which allows roughly one always-on process, one database that self-deletes after 30 days, and no message broker: every one of those limits forces the same concession — collapse the services into a monolith, the databases into one schema, the outbox into in-process dispatch. That deploys, and stops being the system this repository documents. Reasoning, alternatives and the accepted costs: **[ADR-011](docs/adr/adr-011-deployment-topology.md)**; runbook in **[docs/operations/deployment-vm.md](docs/operations/deployment-vm.md)**.
- **Secrets are mounted files, not environment variables.** One file per value under `/run/secrets/`, read through Spring's `configtree` import — `${JWT_SECRET}` still resolves, from the file, with no code change. Environment variables are visible to `docker inspect`, readable from `/proc` by anything sharing a namespace, and inherited by every child process. The larger reason is portability: a Kubernetes Secret mounted as a volume produces the identical layout, so the one row of a Compose→Kubernetes translation that normally forces application changes becomes a no-op. The filename-to-property-name mapping is a framework guarantee the whole scheme rests on, so it is pinned by a test (`FileSecretsConfigTreeTest`) rather than assumed. Generated by `infra/secrets/generate.sh`, which refuses to overwrite — rotating `JWT_SECRET` signs out every user and rotating `POSTGRES_PASSWORD` locks the services out of an initialised database, neither of which should happen because somebody re-ran a setup script.
- **`docker-compose.edge.yml`** — Caddy as TLS terminator, kept in a separate file from the service topology because the edge is the one layer that does *not* survive a platform migration (it becomes an Ingress + cert-manager on Kubernetes, an ALB + ACM on ECS). Splitting them means that migration deletes a file instead of unpicking TLS concerns from a service topology. Caddy rather than nginx+certbot because certificate *renewal* is the part that rots: automatic issuance and renewal, no cron job, no reload hook, no 90-day cliff. `frontend/nginx.conf` needed no change at all — it was already written for a terminator in front of it and deliberately left HSTS to that layer.
- **Nightly `pg_dumpall` backups** to a retained volume (`infra/postgres/backup.sh`), written to a `.partial` file and renamed, so a file with the final name is always a dump that finished. `pg_dumpall` not `pg_dump` because there are eight databases plus their roles, and a restore that recreates seven of eight is not a restore.
- **A `deploy` job closes the loop**: push to `main` → tests → multi-arch images → the VM rolls forward to that SHA → the pipeline asks the *public URL* whether it actually came back, and fails if not. Deployed by immutable commit SHA, never `latest`, so a rollback is re-running the workflow at an older commit. The SSH host key is pinned rather than `StrictHostKeyChecking=no`, which would otherwise hand a deploy key to whatever answers on that address. Skipped entirely when no VM is configured, so forks stay green.

### Fixed — the whole application 500'd for anyone who had just registered

- **A new account got HTTP 500 from every screen.** Register, sign in, and the dashboard, appointments, invoices, records and queue all returned `500 Unexpected error`. The cause is a trap worth knowing: Spring Cloud's circuit breaker wraps a Feign client, and when no fallback factory is registered — deliberate here, because ADR-004 says synchronous calls fail fast rather than serve invented data — it replaces *every* exception with `NoFallbackAvailableException`. So the obvious defence, which four services had written, is dead code in production:

  ```java
  try { return patientClient.me().data().id(); }
  catch (FeignException.NotFound e) { ... }   // never reached
  ```

  It works when the client is mocked in a unit test and never fires against the real wiring, which is precisely why no test caught it. patient-service was answering correctly all along — `404 No patient profile linked to your account yet`, the normal state of every user between registering and completing their profile — and that correct answer was being reported as a server fault. Fixed with `DownstreamFailureAdvice` in platform-starter: one place, all services, translating a downstream 404 to a 404 that tells the user to complete their profile, and an unreachable dependency to the 503 ADR-004 promises. It is deliberately `@Order(HIGHEST_PRECEDENCE)` — the first attempt registered it at the default precedence and it silently never ran, because each service's `ApiExceptionHandler` ends with a catch-all `@ExceptionHandler(Exception.class)` and the first matching advice wins. Safe to run first precisely because it handles exactly one narrow exception type, which a test asserts.
- **A downstream 404 counted as a circuit-breaker failure.** With a 10-call window and a 50% threshold, five 404s in ten calls opened the breaker — and a new user produces four of them just by loading the dashboard. A handful of sign-ups at once could therefore make a completely healthy patient-service unavailable to everyone for 10 seconds at a time. Client errors are now in `ignore-exceptions` across all four services that use a breaker: the breaker exists for a dependency that is down or slow, and a service answering "no" correctly is neither.
- **CSP blocked the app's own stylesheet from loading.** `Executing inline event handler violates 'script-src self'` in the console on every page load. Angular's production `optimization.styles.inlineCritical` defers the main stylesheet as `media="print" onload="this.media='all'"`, and `optimization.fonts.inline` does the same to the Google Fonts links — both inline event handlers, both correctly refused. CSP hashes do not apply to event handlers, so keeping the optimisations would have meant `'unsafe-hashes'` or `'unsafe-inline'`: trading a real script-injection defence for a few milliseconds of render time on an app whose users are signed in all day. Both optimisations are off, with the reasoning recorded in `index.html` next to the links, since `angular.json` cannot carry comments.

### Fixed — found while preparing the deployment

- **Images were built for `linux/amd64` only**, and the deployment target is ARM. Every published image would have failed to start on the VM with `exec format error`. The publish job now builds multi-arch (`amd64` + `arm64`) manifests via buildx, so one tag runs on the VM, on a laptop, and on x86 orchestrator nodes later. This is nearly free only because the Dockerfiles are runtime-only: nothing compiles under emulation, only a `COPY` runs — a decision made for local build speed that turned out to pay off somewhere else entirely.
- **The gateway's CORS origin list was hardcoded to `localhost:4200`/`4300`.** Browsers send `Origin` on same-origin `POST`/`PUT`/`DELETE`, and the gateway rejects an unlisted origin with a bare 403 *before routing* — so the deployed site would have served every read correctly and failed every write with an empty response body. The comment directly above that list already documented this exact symptom from a previous occurrence. Now `${CORS_ALLOWED_ORIGINS}`, defaulting to the two localhost values.
- **`QueueBroadcaster.heartbeat()` was dead code** — written to stop proxies closing idle SSE streams, never scheduled and never called. Harmless while nginx's `proxy_read_timeout` was raised to an hour; a live bug the moment a TLS terminator or CDN joined the path (Cloudflare's free tier drops idle connections at 100s). Now `@Scheduled(fixedDelay = 20s)`, which also reaps subscribers whose browser went away without a clean disconnect. queue-service, previously listed in the README as having no tests at all, now has six.

### Changed — running on a single machine

- **Every container has a memory ceiling, a log ceiling, a health check and a restart policy.** Both ceilings matter more than they look. `-XX:MaxRAMPercentage` is a percentage *of the container limit*, and with no limit set it reads the host's total RAM — eleven JVMs each sizing a heap against 24 GB is how a machine with plenty of memory still OOMs. And Docker's default json-file driver keeps every log line forever, so eleven chatty JVMs fill a 47 GB boot volume in weeks, taking Postgres and Kafka down with it: the most common way an unattended hobby VM dies. Also: SerialGC below 2 GB of heap (G1's concurrent threads cost more than they return at that size, and eleven services' worth of GC threads on four cores is contention nobody asked for), bounded Kafka retention, and `start_period: 240s` because the honest cold-start time for this chain on four ARM cores is minutes.
- **The frontend container no longer publishes a port.** Caddy is the only container binding a host port; nginx is reached over the compose network like everything behind it.
- **The seeder is behind a `demo` profile.** `docker-compose.prod.yml` deliberately had no seeder, which is right for a real clinic — inventing patients in a production database is a data integrity incident, not a convenience — but a portfolio deployment with an empty database demonstrates nothing. A profile makes it a choice rather than something a deployment inherits. `seed.py` gained `_FILE` support so the admin password comes from the mount, not the environment.
- `.gitignore` extended to cover `/secrets/`, `.env.*` (while keeping `.env.example` committed), keys, editor and OS files. The secrets directory defaults to `./secrets`, so this is the guard against a local run leaving real credentials staged.

### Security

- **The public waiting-room board no longer discloses PHI.** `GET /api/queue/board/{doctorId}` and its SSE stream are unauthenticated by design (a lobby TV has no login), but they were serving the full queue entry — every waiting patient's **surname and presenting complaint**. The board component happened to render only the first name, which protects nobody: the payload was one devtools tab away. Added a server-side `BoardSnapshot`/`BoardEntry` projection carrying token number, status, priority, given name and ETA, and nothing else. The doctor console, which legitimately needs names and complaints, now treats an SSE event as a "something changed" signal and re-reads the full picture from the new authenticated `GET /api/queue/console/{doctorId}` — so PHI never travels on the unauthenticated channel at all.
- **Bypassing the gateway can no longer forge an identity.** Every service authorizes from the `X-User-Id`/`X-User-Roles` headers the gateway sets after validating the JWT, and nothing enforced that the gateway was the only way in — while Compose published all nine service ports to the host, making `curl -H "X-User-Roles: ADMIN" localhost:8084/...` full admin access. Two fixes: business-service ports are no longer published (only the gateway and SPA are; Postgres, Kafka, Eureka and Config are bound to loopback), and a new `GatewayTrustFilter` in `platform-starter` **strips** identity headers that arrive without the gateway's shared secret, so the request continues as anonymous and gets a normal 401 rather than being believed.
- **Auth endpoints are rate-limited.** `POST /api/auth/login` was public and unlimited, making password guessing free. Added a per-client-address token bucket at the gateway (`RateLimitGlobalFilter`) on login/register/refresh, returning RFC 7807 `429` with `Retry-After`. Budgets sit above real usage — the first-run seeder registers 7 users and logs in ~12 times within seconds and must never be throttled. Client address is taken from the **rightmost** `X-Forwarded-For` entry, the only one a client cannot spoof.
- **A doctor is no longer entitled to every patient's chart.** `GET /api/records/patient/{patientId}` required only `ROLE_DOCTOR`, so any doctor could enumerate any patient's complete clinical history by id — despite the README advertising relationship-based authorization, and despite a test that appeared to cover it but stubbed the service to throw and asserted only that the controller mapped it to 403. Access now requires a treating relationship (`existsByPatientIdAndDoctorId`, backed by a new index in `V4__encounter_treating_relationship_index.sql`), verified per (patient, doctor) so treating one patient is not a key to another. Same class of hole fixed on `GET /api/appointments/doctor/{doctorId}`, `GET /api/queue/doctor/{doctorId}/day` and `POST /api/queue/doctor/{doctorId}/call-next`, where a caller-supplied doctor id was accepted as proof of identity; the `/schedule` screen now pins a doctor to their own day instead of offering a picker of colleagues.
- **Services refuse to start on a secret published in this repository.** The `careconnect-local-dev-secret-key-please-override-1234` default silently worked in any environment, so forgetting `JWT_SECRET` meant anyone reading the repo could mint an ADMIN token. `InsecureDefaultsGuard` (gateway and identity-service) rejects known-public secrets and secrets shorter than HS256's 256-bit minimum. Fail-closed: the `allow-insecure-defaults` escape hatch defaults to **false**, and docker-compose opts local development in explicitly.
- **Security headers on the SPA.** `nginx.conf` gained CSP, `X-Content-Type-Options`, `X-Frame-Options` and `Referrer-Policy`, re-applied in the static-asset location because a location-level `add_header` discards inherited ones. CSP allows `'unsafe-inline'` for styles only (Angular and Material inject inline styles); `script-src` stays `'self'`. HSTS is deliberately absent — it belongs on the TLS terminator, not this plain-HTTP listener.

### Added

- **Chart access trail — who opened a patient's records.** Every read of clinical data now writes an append-only row to `record_access_log`: acting account, role, patient, encounter, action, self-access flag, and the correlation id tying it back across services. Access control decided who *may* read a chart; nothing recorded who *did*, which is the control clinical software is actually audited on. Three deliberate properties: the log write **shares the read's transaction** (fail-closed — a chart that cannot be recorded as read is not served, at the honest cost of chart reads depending on a write); a **denied** read is not logged, because it disclosed nothing and padding the trail would make "who saw this" answer with people who did not; and it is explicit calls rather than an AOP aspect, so a new read path cannot silently escape the pointcut. **The patient can see their own trail** at `/my-record-access` — a log only the institution can read is an internal control, one the subject can read is accountability. Staff audit any patient (`/patients/:id/access`); admins can ask the reverse question, "what has this account been reading". Covered by 5 integration tests including the denied-read case.

### Removed

- **`laboratory-service`, entirely** — ~2,800 lines, a database, a Kafka topic, a JVM, two frontend routes and a role. It contradicted the project's own scope statement (the README and vision doc both exclude lab orders), was the least-tested service in the repository (one test file), and split the demo into two competing stories. Working code is not a reason to keep code. Full reasoning, alternatives and consequences in **[ADR-010](docs/adr/adr-010-remove-laboratory-service.md)**. Its consumers went with it: `LabEventConsumer` in billing and medical-record, the `lab.events` subscription in notification, the `encounter_lab_reports` link table, and `BillingService.issueForService` (which had no other caller).
- **Five roles that nothing enforced.** `identity-service` seeded LAB_TECHNICIAN, RADIOLOGIST, PHARMACIST, NURSE, BILLING and SUPER_ADMIN; four had **zero references anywhere in the codebase**. A permission model advertising authorities nothing checks is worse than a short one. Reduced to ADMIN, DOCTOR, PATIENT, STAFF. Both removals are **forward** migrations (`V5__drop_encounter_lab_links.sql`, `V3__remove_unimplemented_roles.sql`) rather than edits to already-applied ones — Flyway validates checksums, so rewriting history would stop the services starting against any database that had run them. The role deletion is additionally guarded on the role having no members, so a cleanup migration can never silently strip an account's authority.
- Duplicated comment blocks in `docker-compose.yml` — the "one-shot demo seeder" note had been pasted above `queue-service` and again twice above the seeder itself.

### Added — CI and frontend tests

- **GitHub Actions pipeline** (`.github/workflows/ci.yml`): backend `./mvnw verify` on JDK 21, frontend typecheck + unit tests + build on Node 22, and a compose-config validation job. The repository had issue and PR templates but no pipeline.
  The backend job **asserts that no tests were skipped**. That is the entire reason it exists: Testcontainers tests are annotated `disabledWithoutDocker`, so on a laptop without Docker 15 of them skip and the build still goes green — including every concurrency and event-pipeline test. CI has Docker, so a skip there means something is wrong, and the job fails rather than passing for the same misleading reason a laptop does.
- **First frontend tests**: Karma + Jasmine wired up (the project declared an `ng test` script with no runner installed and no `test` target in `angular.json`, so `npm test` could never have worked), plus 9 specs for `AsyncResource` — the state machine every screen now depends on, including the empty-vs-loading distinction it exists to enforce and the cancel-on-reload guarantee.

### Changed — frontend async states

- **Every async surface now reports failure.** Screens held a bare `signal<T[]>([])` and did `subscribe(r => sig.set(r))`, which collapses three different situations into one empty array: still loading, loaded and genuinely empty, and failed. So a list rendered "No appointments yet" *while its request was in flight* — asserting something the app did not yet know — and rendered the same thing when the request failed. Two screens made it worse by catching the error explicitly and setting an empty list: `my-lab-results` told patients their **lab results did not exist** when the request failed, and `doctor-dashboard` showed "no pending requests" when it could not load them, so a doctor could silently miss bookings awaiting their decision.
- Added `AsyncResource` (`core/http/async-resource.ts`): one request as signals, distinguishing `idle` (nothing chosen yet, so show a prompt not a spinner), `loading` (nothing to show — skeleton), `refreshing` (previous data on screen, keep it and dim it), `ready` and `error`. Cancels any in-flight request on reload, so a search-as-you-type list can't render results for a query the user has moved on from. Not built on Angular's `rxResource`, which is still experimental in 19 and changed shape in 20.
- Added `<cc-skeleton>` (layout-preserving placeholders rather than a centred spinner, which discards the layout and makes the page jump) and `<cc-error>` (inline message from `humanizeError`, with retry). Both announce themselves via `aria-busy`/`role`, and the shimmer respects `prefers-reduced-motion`.
- Converted the patient journey and the busiest staff screens: **book, my-appointments, my-invoices, my-records, my-lab-results, patient-list, directory, patient-dashboard**. Booking gained the states it most needed — slot loading is deferred until a doctor and date are chosen, a lost race for a slot is reported inline next to the button (per the policy `error.interceptor.ts` documents, which this screen previously contradicted by toasting everything) and refreshes the slot list, and the submit button can no longer be double-clicked.
- **Two dashboard bugs that misled users.** `patient-dashboard` set "complete your profile" on *any* error from the profile call, so a brief patient-service outage nagged patients to create a profile they already had; `doctor-dashboard` did the same with "submit your credentials". Both now key off a 404 only. `doctor-dashboard` also replaced a `setTimeout(…, 1500)` guess after completing a visit — the chart is created asynchronously by medical-record-service consuming `AppointmentCompleted`, so the message now says the chart "is being created" rather than claiming it exists, and refreshes twice instead of betting on one delay.
- The public waiting board shows "Reconnecting…" instead of a blank screen when it cannot reach the server. A kiosk has nobody to click retry, and an unexplained empty board reads to staff as an empty queue.

### Fixed — three defects that had never run anywhere

Found within minutes of CI running the Testcontainers tests for the first time. All three
were invisible locally because the tests were skipping and the reactor died before three
modules were even reached.

- **Recording a payment violated `payments.invoice_id NOT NULL`.** `Invoice` mapped payments as a unidirectional `@OneToMany` with `@JoinColumn`, so Hibernate inserted the `Payment` with a null FK and back-filled it with a second `UPDATE` — which the `NOT NULL` rejected. **Paying an invoice had never worked against a real database.** `BillingControllerTest` mocks the service and `BillingIntegrationTest` is `disabledWithoutDocker`, so the only test touching the real mapping had never executed. `Payment` now owns the FK (`@ManyToOne` + `mappedBy`), written on the insert itself.
- **`AppointmentIntegrationTest` tests fought over the same slot.** Three of them booked the same doctor at the same "next Monday 10:00" against a shared container with no cleanup, so whichever ran second hit the exclusion constraint and failed with a real `AppointmentConflictException`. The doctor id is now scoped per test, making each independent by construction rather than relying on a `@BeforeEach` truncate that the next author has to remember.
- **A test asserted a lazy collection on a detached entity.** `paid.getPayments()` ran after the transaction had committed. Production survives this only because `BillingController` is `@Transactional` — itself the layering smell flagged for follow-up. The test now re-reads inside a transaction, which is the stronger assertion anyway: it proves the row reached the database.

### Fixed

- **The live queue did not work in the deployed stack at all.** `nginx.conf` proxied the SSE endpoint through its generic `/api/` block, where nginx's default `proxy_buffering on` holds an event stream instead of forwarding it and the default 60s `proxy_read_timeout` kills an idle one — which, for a waiting-room board, is most of the day. It worked under `ng serve` (which proxies unbuffered), which is exactly why it went unnoticed: the flagship feature was broken only in the configuration the README tells you to run. Added a dedicated `location /api/queue/stream/` with `proxy_buffering off`, `proxy_http_version 1.1`, a cleared `Connection` header and a 1-hour read timeout.
- **Every appointment check-in produced a queue entry named "Patient".** `QueueController.checkIn` passed `request.patientId() == null ? "Patient" : "Patient"` — a ternary whose branches were the same literal — so the board and the doctor's console labelled real patients "Patient" and their doctor "Doctor". Names are now resolved from patient-service and provider-service, via a new `GET /api/providers/doctors/{id}/summary` (name only, any authenticated caller, mirroring the existing patient summary) so a patient checking themselves in can resolve their doctor's name without being able to read fees or registration details.
- **A patient could check another patient into a queue.** `checkIn` took `patientId` straight from the request body with no ownership check. A PATIENT caller is now always checked in as themselves, resolved from their own account and ignoring the submitted value — the same rule booking already followed.
- **The outbox relay marked its own thread interrupted on every failure.** `Thread.currentThread().interrupt()` sat inside `catch (Exception e)`, so an ordinary broker error set the interrupt flag on the scheduler thread and caused unrelated later operations on it to fail spuriously. The flag is now restored only for a genuine `InterruptedException` (graceful shutdown), which is the one case that warrants it.
- **One unpublishable event could block all events forever.** `lockPending` orders by `created_at` and the relay `break`s on failure, so a single poison payload at the head of the queue stalled every event behind it indefinitely — with `attempts` recorded but never read. The relay now distinguishes the two failure modes, which is the whole subtlety: anything Kafka marks `RetriableException` (timeouts, no leader) stops the batch **without** consuming an attempt, because a long outage would otherwise burn the budget and abandon healthy events; a record-specific failure (payload too large, topic rejected) consumes an attempt and moves on. After `max-attempts` the event is excluded from polling and left in `outbox_events` with its `last_error`, so the table doubles as the dead-letter store and nothing is silently discarded. New `careconnect.outbox.dead` gauge and `careconnect.outbox.abandoned` counter. Covered by 8 unit tests.
- **No graceful shutdown.** In-flight requests were killed on every redeploy. `server.shutdown: graceful` with a 25s drain, plus `stop_grace_period: 30s` on each service in compose — without which Docker SIGKILLs at 10s and the Boot setting would be decorative.
- Removed a dead `findByPublishedAtIsNullOrderByCreatedAt` from all five outbox repositories: declared, never called.
- **`mvn test` failed on a clean checkout, and three modules' tests had never run.** `MedicalRecordControllerTest` and `BillingControllerTest` are `@WebMvcTest` slices whose controllers depend on Feign clients; the slice has no `FeignClientFactory`, so the context failed to load and all 9 tests errored. The reactor died at medical-record-service, meaning billing, queue and laboratory tests were **skipped entirely** and had never been verified. Both tests now mock their Feign collaborators, and the full reactor passes.
- Added a **Maven wrapper** (`./mvnw`, script-only so no binary is committed). The documented build command required a globally installed Maven, which a clean machine does not have.
- Pinned `maven-compiler-plugin` and `maven-surefire-plugin` versions. Because the build imports the Boot BOM rather than inheriting `spring-boot-starter-parent`, nothing managed plugin versions and Maven warned on every run that the build was not reproducible.

### Changed

- Consolidated five byte-identical `FeignConfig` classes (appointment, billing, laboratory, medical-record, queue) into one `IdentityForwardingInterceptor` in `platform-starter`, which is what that module exists for under ADR-001. It also attaches the gateway shared secret, and reads it from configuration rather than forwarding the inbound header, so an internal call made outside a request context (from a Kafka consumer) still authenticates.
- Corrected the testing chapter of the SRS, which listed `@DataJpaTest` and UI tests as **Built** when neither exists, and added a "known gaps" section recording that queue-service has no tests and that 15 Testcontainers tests skip silently without Docker.

### Added
- **Laboratory module (Phase A) — the first hospital service beyond the clinic core.** New `laboratory-service` (port 8089, database-per-service) implementing the diagnostics half of the clinical flow *Consultation → Lab Tests → Results*. A seeded test catalogue (CBC, LFT, KFT, Lipid, TSH, HbA1c, Urine, CRP) with per-analyte reference and **critical** ranges; a lab-order aggregate with a server-enforced state machine (ORDERED → COLLECTED → IN_PROCESS → REPORTED → VERIFIED, plus REJECTED/CANCELLED); barcoded accession numbers on sample collection; automatic result flagging (NORMAL/HIGH/LOW/CRITICAL) with critical values raising a `LabResultCritical` alert to the ordering doctor *before* verification; and senior **verification** that releases the report. Events on `lab.events`: `LabRequested` (billing raises the charge, idempotently), `SampleCollected`, `LabResultCritical`, `ReportUploaded` (medical-record links the report into the patient's chart; notification-service emails the patient). Prices are snapshotted onto the order at placement. New UIs: a doctor **lab-order panel** embedded in the encounter editor (pick tests, priority, indication; see status and released values inline), a technician **worklist** (collect → process → enter results → verify, the UI only ever offering the legal next transition), and a patient **lab results** view (verified reports only, abnormal values flagged with guidance to discuss with their doctor). Additional roles seeded in identity-service (LAB_TECHNICIAN, RADIOLOGIST, PHARMACIST, NURSE, BILLING, SUPER_ADMIN). Domain unit tests for result-flag classification including critical-takes-precedence.
- **Full Software Requirements Specification** (`docs/srs/`, 14 documents, 27 chapters): business objectives and stakeholders; functional requirements for all 21 modules with priority and honest Built/Partial/Planned status; 61 non-functional requirements with measurable targets; 10 roles with a complete permission matrix including relationship-level rules; step-by-step user stories per role with acceptance criteria; end-to-end workflows and 60+ numbered business rules; UI design system, dashboard and navigation specifications; production database design per service with indexing strategy and ERD; REST API contracts with error semantics; microservice map, Kafka topic and event catalogue with reliability model; authentication, layered authorization, logging, monitoring; deployment (local, Kubernetes, CI/CD) and testing strategy; and a phased 15-week roadmap to complete the remaining modules.
- **Doctors can now join two ways, and both make sense**: an administrator hires them (Staff → Add staff member), *or* a doctor self-registers like a patient and submits credentials — qualification, medical registration number, experience, fee — which stay **PENDING** and invisible to patients until an administrator verifies them (`/doctor-approvals`). Self-signup without that gate would let anyone claim to be a cardiologist; the directory query now filters on `verification = APPROVED`, so an unverified doctor cannot be found or booked. Signup page lets you pick "I'm a patient" or "I'm a doctor"; a doctor account with no profile is guided straight to the credentials form instead of an empty dashboard.
- **The doctor is now part of the booking decision** — the workflow gap that made the system feel disconnected. A patient's booking arrives as REQUESTED in the *doctor's own inbox*; the doctor accepts (→ CONFIRMED) or declines (slot freed, patient notified) from their dashboard. Ownership is resolved server-side from the profile linked to their account, never from a caller-supplied id, so a doctor can only decide on their own appointments. Front desk retains the ability to confirm on a doctor's behalf for phone bookings.
- **Staff onboarding**: `Staff → Add staff member` creates the login, the role, the professional profile (department, specialization, fee) and the weekly schedule in one submit, then displays the credentials to hand over. Staff directory with revoke/restore access and password reset (identity-service gained `GET /api/users`, activate/deactivate and admin password reset).
- **Live Care Flow — the differentiating feature**: new `queue-service` implementing a real-time OPD queue. Sequential per-doctor tokens (row-locked counter), triage priority that reorders groups without breaking arrival fairness within them, a wait-time estimator built on the median of each doctor's last 20 consultations, and **Server-Sent Events** streaming full queue snapshots to any screen. Ending a consultation publishes `ConsultationCompleted`, which appointment-service consumes to complete the visit — cascading into chart creation, invoicing and notification. Three new UIs: doctor console (call/recall/start/complete with live updates), patient "my place in the queue" view with live position and ETA, and a **public waiting-room display board** (`/board/:doctorId`) designed for a lobby TV — no login, high contrast, self-updating. ### Fixed
- **First real end-to-end run surfaced a chain of bugs that unit/slice tests couldn't see** — booking, "my invoices/records/queue-status/lab-results", the doctor charting workflow, and the lab worklist were all broken for real users despite passing tests, because nothing had exercised the full request path with genuine cross-service data before:
  - **Booking was broken for every user**: `ProviderClient.bookingInfo`'s Feign call serialized the `date` query param with the JVM's locale-dependent short-date formatter (`7/29/26`) instead of ISO-8601, so provider-service's `@DateTimeFormat(iso = DATE)` parser rejected every request with a 500. Fixed by annotating the Feign client parameter to match the receiving controller.
  - **"My Invoices", "My Records", "My Queue Status" and "My Lab Results" all returned empty or 500 for every patient/doctor**: four services (billing, medical-record, queue, laboratory) treated the raw JWT subject (identity's user id) as if it were patient-service's or provider-service's own id, instead of resolving it — a distinction appointment-service already got right via `resolveOwnPatientId()`/`resolveOwnDoctorId()`. Added the same Feign-based resolution (with identity-forwarding interceptor and circuit breaker, matching ADR-004) to the three services that lacked it.
  - **`GET /api/providers/departments` was allowlisted at the gateway but not in provider-service's own `SecurityConfig`**, so the gateway stripped identity headers for it (believing it public) and provider-service then demanded them — a permanent 401 for a route declared public. This alone silently blocked the demo seeder from ever completing for the past several days. Added the matching `permitAll()`.
  - **Several read endpoints threw `LazyInitializationException`**: `Doctor.department`, `Encounter.{diagnoses,prescriptions,amendments}`, `Invoice.payments`, and `TestCatalogue.analytes` were all mapped to DTOs in the controller, after the service's transaction (and Hibernate session) had already closed. Fixed with `@EntityGraph` where a single collection was involved, or a controller-level `@Transactional` where multiple collections made eager-fetch impossible.
  - **That eager-fetch attempt itself was invalid where it existed**: `EncounterRepository`/`LabOrderRepository` had `@EntityGraph` trying to eager-fetch two `List`-typed collections at once, which Hibernate rejects (`MultipleBagFetchException`) — a latent bug that had never been reached because the identity-resolution bug above always failed first. Removed the invalid entity graphs in favor of the transaction-scoped fix above.
  - **appointment-service's inter-service call timeout (4s) was tuned for a fully warmed JVM**: this stack already runs JIT capped at C1 for faster local startup (`docker-compose.yml`), which makes steady-state execution slower — under real concurrent load the 4s timeout tripped on calls that weren't actual outages. Raised to 8s; still fail-fast, just calibrated to this environment (ADR-004 doesn't mandate a specific value).
  - `infra/seed/seed.py` hardened to match: raised its HTTP timeout, added retry-with-backoff for transient 5xx/timeout responses, and stopped treating a 409 on invoice payment (idempotency guard correctly rejecting a duplicate) as a failure.
- Local stack tuned for laptops: C1-only JIT and capped heap per service (JVM startup was taking 200+ seconds under contention), per-container memory limits, and realistic healthcheck grace periods — previously slow starts were reported as failures and Compose aborted the remaining services.
- **The system shipped unusable on a fresh machine**: compose defaulted `SEED_ADMIN_PASSWORD` to empty, so identity-service skipped admin creation — with no administrator, nobody could hire doctors, and with no doctors every downstream screen (booking, records, invoices) was permanently empty. Local dev now always creates an admin, the demo seeder runs as part of the normal `platform` profile, and the login page lists one-click demo accounts for all three roles.
- **Gateway identity headers were being erased by its own config**: `RemoveRequestHeader` default-filters (route-scoped) ran after the JWT global filter and deleted the `X-User-*` headers it had just set, so every authenticated request reached services anonymously and 401'd. Stripping now happens inside `JwtAuthGlobalFilter`. Also: the Angular interceptor no longer ends the session when a *replayed* request fails — only a failed refresh does, so server-side auth bugs surface as errors instead of silent login redirects.
- Single-flight token refresh in the Angular `AuthService`: concurrent 401s previously triggered parallel refreshes, and the backend's rotation replay-detection (correctly) revoked the session — users were logged out mid-navigation.
- Gateway CORS now allows both SPA origins (4200 dev / 4300 container) — the containerized frontend's POSTs were rejected with an empty 403 because same-origin POSTs still carry an `Origin` header.
- Container health signals: healthchecks now probe `/actuator/health/readiness` (readiness/liveness groups defined centrally) instead of the full aggregate, and Eureka dev intervals relaxed to 10s/10s/30s — the previous 5s fetch interval doubled as the client's task timeout and produced cascading false-unhealthy containers on cold starts. Startup grace raised to 60–90s.
- Compiler `-parameters` flag in the parent pom (Spring 6.1+ requirement for `@RequestParam` name resolution — starter-parent sets it implicitly, custom parents must not forget it). Explicit 401 entry points in service security configs (default was a misleading 403 for anonymous). Patient error handler now covers `AccessDeniedException` broadly.
- `@EnableJpaAuditing` moved off the application class into `JpaAuditingConfig` (was breaking `@WebMvcTest` slices: "JPA metamodel must not be empty"). Test hermeticity: test-classpath `application.yml` prevents tests from contacting a running config-server/Eureka.
- Test infra on modern JDKs: Byte Buddy override + experimental flag (devs on JDK 21–25; bytecode remains Java 21). Testcontainers test now skips visibly instead of failing when Docker is down.
- Gateway 503 on `/api/_platform/config-health`: config-server had no Eureka client, so `lb://config-server` could never resolve. Config-server now registers; dev registry propagation tightened (5s fetch/renewal, 5s server cache).
